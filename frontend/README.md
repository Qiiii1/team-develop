# OK啊 · 最新高保真前端

> `main` 中请在**仓库根目录运行 `npm start`**，使用真实团队后端和现有 HTTPS 配置。新版已接入登录、团队、邀请、个人配置、私人 AI 与资料摘要；工作台／文件存储／黑板仍为本地原型。详见[前后端整合说明](../docs/FRONTEND-INTEGRATION.md)。下文保留上游前端原型的独立启动说明，`node server.mjs` 不是整合版启动方式。

本分支直接存放本次制作的“初始页-高保真”页面、IP素材，以及资料解析配套服务，不包含旧版前后端项目。

## 历史单人原型启动（非 main 整合版）

需要 Node.js 24 和 Python 3.11 或以上。在本目录运行：

```sh
python -m pip install --target .runtime -r requirements.txt
node server.mjs
```

打开 http://127.0.0.1:4178/ 。

## 页面

- `index.html`：初始页、历史项目和新建项目弹窗、首次账号设置。
- `project.html`：首页场景、六个工位、独立桌椅及人物图层、头像与姓名、邀请和举手。
- `workbench.html`：工作台任务、时间和分工视图，接自 `frontend-uuuuu`（549f0f9）；复用常驻侧栏和邀请/举手。任务数据为按项目隔离的浏览器本地原型，AI分工暂为演示。
- `library.html`：知识库、按阶段和部分上传、AI摘要确认、资料编辑及历史对话。
- `blackboard.html`：黑板问题、回复进度、归档，来源 `frontend-mmm`（324eb91）。
- `personal-ai.html`：个人AI原型、引用项目内容、附件和任务确认，来源同上。
- `account.html`：账号名字、九款IP选择、DeepSeek配置和连接检查。
- `architecture.html`：初始页备用入口。

## 历史单人原型的资料解析服务

账号管理填写并保存 DeepSeek 密钥后，知识库“提取资料”使用该配置。默认接口 `https://api.deepseek.com/v1`，模型 `deepseek-flash`。PDF、DOCX、XLSX先在本地提取文字，再交给DeepSeek生成简短摘要；扫描PDF尚不支持OCR。保存配置不调用模型，“检查连接”和实际提取会调用模型。

密钥仅保存在本机，不回显、不提交Git。单人旧配置使用 `.api-settings.local.json`；邀请流程建立的账户、会话、项目座位和个人API配置使用 `.invitation-state.local.json`。两个文件都被Git忽略。资料元数据保存在浏览器localStorage，原文件保存在IndexedDB。

## 历史单人原型的交互说明

- 工作台任务、日期拖动、阶段管理和分工，以及首页进度、个人任务使用同一份项目本地数据
- 任务必须分配负责人才能开始，必须上传成果并由指定验收人通过后才算完成、才进入知识库
- 工作台和个人AI均可提交、验收及打开成果；已完成任务保留，重新修改时可选择保留或删除资料
- 个人AI只引用当前项目知识库文档；私人AI聊天与举手对话仍为演示回答
- 邀请按钮生成项目邀请链接，已有本机会话直接加入，新用户在弹窗填写名字、人物及API配置后自动分配空座位，重复加入不重复占座
- 邀请身份是本机原型的Cookie会话，不是正式用户名/密码或第三方登录；尚未接入backend分支的生产账号体系
- 服务仅监听本机127.0.0.1，邀请链接也仅适用于当前可访问的本机服务；跨设备使用需要另行部署
- 账户和座位由本地服务保存，任务、知识库和黑板数据仍是浏览器本地数据，尚未实现跨设备同步

不含密钥、本地用户数据、历史备份、测试截图或运行依赖。
