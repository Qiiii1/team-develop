# 系统管理后台

更新：2026-10-31。入口为 `/admin`；也可从系统管理员账号左侧的「系统管理」进入。

## 能做什么

- **概览**：全部账号、启用账号、全部团队、使用中团队、已配置 AI 的账号数、有效登录会话数。有效会话不表示成员当前在线。
- **账号管理**：按登录名或姓名搜索、分页查看、启用或停用账号、强制所有设备退出登录。停用会立即撤销现有会话；重新启用后需要重新登录。
- **团队管理**：搜索与分页查看所有团队、查看成员、修改团队名称、调整普通成员与团队管理员权限、移除非发起人成员、停用与恢复团队。
- **操作记录**：记录系统管理员操作的执行人、时间、动作与对象。修改和记录写入同一数据库事务，失败操作不会留下成功记录。

系统管理权限与团队管理员权限分别保存。团队发起人和团队管理员默认无法访问系统管理接口。后台不显示密码、密码派生值、API Key、加密密文、会话令牌或邀请令牌。

## 设置系统管理员

部署电脑上的操作者可为已经注册且启用的账号授权：

```sh
npm run admin:grant -- 你的登录名
```

该命令采用与网页服务相同的 `.env.web.local`、数据库路径与数据库迁移。授权完成后刷新网页即可，原登录会话可继续使用。授权操作记为「本机部署者」。命令不会创建默认密码，也不会读取成员的 API Key。

新注册账号默认是普通账号；新部署不自动将第一个注册者设为系统管理员，需要通过上述本机命令明确授权。网页没有公开的系统管理员授权接口。

## 停用与恢复

- 账号停用保留其团队关系和个人配置，避免误删数据；重新启用不会恢复旧会话。
- 团队停用保留团队与成员数据，普通成员将无法进入团队或进行团队操作；成员仍能使用自己的账号及其他团队。
- 停用团队会撤销该团队现有邀请。恢复团队后，管理员需要重新生成邀请。
- 团队发起人不能通过成员接口被移除或降级。当前后台尚未提供发起人转让。
- 当前系统管理员不能停用自己的账号。至少保留一个可用系统管理员。
- 账号、团队与成员更改都校验修订号，旧页面提交冲突时返回 409，刷新后再操作。

账号停用、强制退出、团队启停及移除成员需要在界面中确认。账号和团队不提供永久删除；密码重置、发起人转让、跨服务运维和模型消费明细尚未实现。

## 数据与验证

本次增加 `users.is_system_admin`、`users.admin_revision`、`teams.archived_at` 和 `admin_audit` 表。迁移保留已有账号、团队和模型配置，原有账号默认没有系统管理权限；本机授权独立执行。

验证覆盖：

- 未登录、普通账号及团队管理员无法读取或修改系统管理数据；公开注册不能提交权限字段自行提权。
- 管理员请求继续校验 Session、CSRF、同源、输入字段白名单和响应字段白名单。
- 停用账号使现有会话失效，重新启用仍需重新登录；强制退出不删除账号。
- 团队停用阻止成员访问、操作和邀请加入；恢复保留成员，已撤销邀请继续失效。
- 团队发起人保留、普通界面的权限变化会使后台旧修订冲突、成员被移除后失去访问权。
- 账号和团队列表的搜索与分页；模型配置状态准确且没有凭据字段。
- 旧 M1 数据库原地升级，既有账号及团队保留，普通账号不会被自动提升。
- Chrome 独立管理员/普通账号会话中的完整管理流程、直接访问 `/admin` 的权限提示、375px 手机布局。

类型/语法检查和生产构建通过；当前完整验证范围见[核心协作版](核心协作版.md)。运行 `npm test`、`npm run test:browser` 和 `npm run check` 可复验。截图见 `artifacts/admin-overview.png` 与 `artifacts/admin-mobile.png`；测试采用临时数据库，不向实际试用库添加模拟成员。
