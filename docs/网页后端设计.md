# 团队 Harness · 网页后端设计

日期：2026-10-31。状态：第一阶段（M1）已实现；M2–M4 仍为实施计划。运行与验证范围见[第一阶段试用指南](网页第一阶段试用.md)。

## 1. 本轮已确认的前提

- 产品采用独立网页应用，运行在部署者自己的电脑上。
- 同一局域网的队友通过浏览器连接这台电脑。
- 每位成员配置自己的 API Key，由后端按当前登录成员身份调用模型。
- 个人 AI 使用本人的额度；公共讨论中谁触发 @AI，就使用谁的 Key。
- 密钥由部署电脑上的后端处理、加密保存。网页版的私人数据也保存在部署电脑上，通过账号权限隔离。

此前 dsh 插件的安装、身份绑定和本机模型桥接不作为网页版的实现前提。此前产品定义中的共享与确认原则继续作为设计依据；2026-10-22 复盘中的候选功能仍未自动纳入首版。

## 2. 技术方案

| 部分 | 方案 |
| --- | --- |
| 运行环境与语言 | Node.js 受支持的 LTS 版本、TypeScript；实施时锁定具体版本 |
| HTTP 服务 | Fastify；同源提供网页与 `/api/v1` 接口 |
| 数据校验 | Fastify JSON Schema；请求与响应都定义字段，敏感信息不进入响应结构 |
| 数据库 | SQLite，本地磁盘文件，启用外键、WAL 和合理的 busy timeout |
| 数据访问 | Drizzle ORM；提交可审阅的 SQL 迁移文件 |
| 登录 | 服务端 Session，随机令牌放入 HttpOnly Cookie，数据库只保存令牌摘要 |
| 密码 | 使用 Node.js `crypto.scrypt` 异步派生，随机独立盐与可升级参数 |
| Key 加密 | AES-256-GCM；每次保存使用新 nonce，关联用户及配置 ID；独立保存主密钥及版本 |
| 实时同步 | WebSocket 推送已提交事件；HTTP 负责业务写入、历史与断线补取 |
| 模型接入 | 独立 provider 适配层；先接通现有 DeepSeek，后续按需扩展 |
| 运行方式 | 构建后 Node.js 直接启动；Docker 可在后续作为打包选项 |

后端先运行一个进程，内部按身份、团队、AI、讨论、成果、背景与决定模块划分。SQLite 文件只由该服务读写，成员通过 API 访问。

浏览器 → 同源网页/API/WebSocket → Fastify → SQLite；AI 调用由 Fastify 所在电脑访问模型服务商。

## 3. 开发顺序与验收

### M1：账号、团队和个人配置

第一个交付是可在浏览器中操作的多人基础流程：

1. 发起人注册、登录，创建一个空团队。
2. 发起人生成邀请，队友用独立账号加入。
3. 双方看到同一份真实成员名单。
4. 双方分别配置、替换、删除自己的 Key；保存配置不自动发起付费模型请求。
5. 退出、重新登录、重启服务后，账号、团队和配置仍然存在。

必须验收：未登录访问被拒绝；团队外用户无法读取团队；成员不能读取或覆盖别人的 Key；邀请码的失效、撤销、次数限制在后端生效；数据库中没有明文密码或明文 Key。此阶段不宣称 AI 对话已接通。

### M2：个人对话与公共讨论

- 创建团队关联的私人对话与公共讨论。
- 先打通个人 AI，再接公共区的显式 @AI。
- 用两套浏览器会话和模拟模型接口确认：A、B 分别调用自己的 Key，公共 AI 使用触发者的 Key，私人消息不会被另一账号读取。
- 保存请求状态、实际使用的模型、用量及上下文版本；处理超时、取消、服务商错误。
- 同一请求重放不再自动调用模型；不对可能已经计费的未知结果自动重试。

### M3：共享成果、背景与决定

- 私人草稿 → 本人预览 → 明确确认发布。
- 成果保留作者、来源链接和依据版本。
- 决定经过指定确认人确认后生效，背景保留历史版本。
- 新对话采用最新背景；已有对话保留原快照，更新由本人选择。
- 旧依据成果发布前记录作者复核，保留实际引用版本。

### M4：实时体验与局域网交付

- 公共消息和共享资料更新推送，断线后按游标补取。
- 在线状态由连接和心跳维护；动画在前端表达。
- 固定局域网入口、开机启动方式、数据库与主密钥备份恢复说明。
- 两台真实设备验收登录、加入、讨论、各自调用 AI、权限隔离及重启恢复。

M2、M3 已按 HTTP 流程验收后再增加实时推送；WebSocket 不承担数据持久化职责。

## 4. 数据表设计

所有 ID 由服务端生成；时间以 UTC 保存。带团队归属的数据必须在后端校验当前成员资格。私人数据还须校验作者或对话所有者。

### M1 建表

| 表 | 核心字段与约束 |
| --- | --- |
| `users` | `id`, `username_normalized`（唯一）, `display_name`, `password_hash`, `created_at`, `disabled_at` |
| `sessions` | `id`, `user_id`, `token_hash`（唯一）, `expires_at`, `revoked_at`, `created_at` |
| `teams` | `id`, `name`, `owner_id`, `revision`, `created_at`；目标允许为空 |
| `team_members` | `team_id`, `user_id`, `role`, `joined_at`, `removed_at`；团队与用户组合唯一；角色为 owner/admin/member |
| `team_invites` | `id`, `team_id`, `token_hash`（唯一）, `created_by`, `expires_at`, `max_uses`, `used_count`, `revoked_at` |
| `user_ai_configs` | `id`, `user_id`, `provider_id`, `model`, `key_ciphertext`, `nonce`, `auth_tag`, `key_version`, `revision`, `updated_at`；首版每用户一份当前配置 |

创建团队及 owner 成员写入同一事务。加入团队时，在同一事务中检查邀请码并消耗名额；重复加入不重复计数。移除成员后立即失去团队读写与订阅权限。管理员授权只由 owner 操作；决定确认人另行指定。

M1 实现补充：`users.ai_config_revision` 保存单调递增的配置修订号，删除配置后也不重置，避免旧页面覆盖重新创建的 Key。管理员可通过 `GET /teams/:teamId/invites` 查看邀请元数据，原始令牌只在创建时返回。

### M2、M3 逐步增加

| 表 | 职责 |
| --- | --- |
| `conversations` | 团队归属、public/private 类型、私人所有者、当前背景快照 ID；私人所有者不可由他人修改 |
| `messages` | 对话、作者、角色、正文、创建时间、AI 请求 ID；按游标分页 |
| `ai_requests` | 触发者、对话、配置版本、模型、状态、输入消息、背景快照、用量、错误分类、幂等标识；不保存原始 Key |
| `drafts` | 团队、作者、内容、修订号；仅作者可读写，发布操作必须显式触发 |
| `shared_artifacts` | 团队、作者、内容、来源链接、源草稿修订号、发布时间、幂等标识 |
| `decisions` | 团队、标题、指定确认人、当前生效版本 ID、修订号 |
| `decision_versions` | 决定 ID、版本号、内容、来源、提出人、确认人、确认时间；决定与版本号组合唯一 |
| `background_versions` | 团队、版本号、确认的目标及背景、来源、包含的决定版本、确认人、时间；已确认版本不可覆盖 |
| `context_snapshots` | 团队、背景版本、纳入的成果及决定版本引用、当时文字快照；不可变 |
| `conversation_context_changes` | 对话、前后快照、采用人、时间；保留用户主动更新背景的历史 |
| `artifact_decision_refs` | 成果、决定及实际版本、作者复核时对照的生效版本、复核内容和时间 |
| `team_events` | 单调递增游标、团队、事件类型、实体 ID、必要的公共摘要、时间；只写团队可见事件 |

业务记录与对应持久事件在同一事务中提交。决策确认、背景生效和草稿发布要校验预期修订号；冲突返回 409。成果引用、来源消息和确认人必须属于同一团队；必要时使用组合外键保证归属一致。

## 5. HTTP 接口草案

统一前缀 `/api/v1`。服务端从 Session 识别操作者，不接受客户端提供的 userId 作为授权依据。接口使用 JSON Schema、大小限制和响应白名单。

### M1 接口

| 方法 | 路径 | 用途与权限 |
| --- | --- | --- |
| POST | `/auth/register` | 注册；首版使用用户名和密码，不依赖邮件或短信服务 |
| POST | `/auth/login` | 登录，创建会话；限制尝试频率 |
| POST | `/auth/logout` | 撤销当前会话并清 Cookie |
| GET | `/me` | 当前账号及会话状态，不返回密码或 Key |
| GET / POST | `/teams` | 列出本人团队 / 创建空团队并成为 owner |
| GET | `/teams/:teamId` | 团队成员读取团队基本资料 |
| GET | `/teams/:teamId/members` | 团队成员查看真实成员名单 |
| POST | `/teams/:teamId/invites` | owner/admin 创建带过期时间的邀请；原始令牌只在创建时返回 |
| DELETE | `/teams/:teamId/invites/:inviteId` | owner/admin 撤销邀请 |
| POST | `/teams/join` | 登录用户提交邀请令牌加入团队 |
| PATCH | `/teams/:teamId/members/:userId` | owner 授予/收回管理员；不能直接改写 owner |
| DELETE | `/teams/:teamId/members/:userId` | owner 可移除非 owner；admin 只可移除普通成员 |
| GET | `/me/ai-config` | 只返回 configured、provider、model、revision 等元数据 |
| PUT | `/me/ai-config` | 保存/替换本人配置；省略 Key 时保留原 Key；显式 revision 防止覆盖 |
| DELETE | `/me/ai-config` | 清除本人配置 |

注册本身不赋予任何团队资料访问权。用户名仅是登录标识，显示姓名允许重复。owner 转让、找回密码和跨设备管理作为后续流程设计，不由普通成员接口隐式实现。

### M2、M3 接口族

- `POST /teams/:teamId/conversations`：新建私人对话；公共讨论由服务创建固定入口，客户端不能将私人对话直接改为公开。
- `GET /conversations/:conversationId/messages`：校验归属和可见性后分页读取。
- `POST /conversations/:conversationId/messages`：发送人的消息；普通公共消息不触发模型。
- `POST /conversations/:conversationId/ai-requests`：本人显式请求 AI；携带已存在的输入消息 ID、幂等标识和预期背景快照。
- `GET /ai-requests/:requestId`：读取本人调用状态；公开回答通过公共消息接口获取，不公开个人用量配置。
- `/teams/:teamId/drafts`：本人草稿 CRUD；`POST /drafts/:draftId/publish` 确认发布具体修订，事务内检查依据并记录复核。
- `/teams/:teamId/artifacts`：读取已分享成果；发布后修订要保留历史，不能隐式覆盖引用依据。
- `/teams/:teamId/decisions`、`/decisions/:decisionId/versions`、`/decisions/:decisionId/confirm`：提出决定、提出新版本、指定确认人使版本生效。
- `/teams/:teamId/backgrounds`、`/backgrounds/:backgroundId/confirm`：提出、确认新背景版本。首版默认由 owner/admin 确认背景，作为实施默认，可后续改为专门授权。
- `POST /conversations/:conversationId/context`：私人所有者明确采用新快照；已有消息与请求保留原依据。
- `GET /teams/:teamId/events?after=...`：断线补取有权限查看的持久事件。

共用错误码：400 输入错误，401 未登录，403 无权限，404 无可访问记录，409 版本或幂等冲突，429 请求过频，502/504 模型服务异常/超时。失败响应不透传模型服务商的原始敏感内容。

## 6. AI 调用与密钥边界

1. 校验会话、当前团队资格和对话可见性；锁定当前操作者。
2. 从数据库读取操作者本人的模型配置，客户端不能指定替别人付费的账号。
3. 构建上下文：私人对话仅纳入本人的消息和有权限的团队资料；公共讨论仅纳入公共资料。公共调用不能混入触发者的私人历史。
4. 写入带幂等标识的请求记录及配置/背景版本，随后在事务外调用模型。禁止跨网络调用期间持有 SQLite 写锁。
5. 将回答、来源请求、用量和状态写入数据库。公共回答公开，Key 不进入消息、事件、错误或日志。
6. 每个成员有独立的并发限制；A 正在调用不应阻止 B 调用。进程重启后未完成请求标记为中断/结果未知，不自动重新计费调用。

浏览器只能配置本人模型信息，服务商地址由部署者维护的注册表决定；首版先提供 DeepSeek。自定义兼容服务商地址如需增加，由部署者配置，避免普通成员让后端访问任意内网地址。

部署者持有数据库与加密主密钥，因此网页服务的加密用于保护存储文件，不构成对部署者的端到端保密。此边界应在成员首次配置页用简短文字说明。

## 7. 局域网运行与持久化

- 服务监听可配置地址：本机开发默认 `127.0.0.1`，局域网交付显式绑定指定内网地址或 `0.0.0.0`。
- 成员访问部署电脑的内网 IP/本地域名；固定 DHCP 地址，配置允许的 Host 与 Origin。`0.0.0.0` 仅为监听配置，不作为浏览器访问地址。
- 实际传输密码和 Key 的多人使用环境配置 HTTPS；可以直接由 Fastify 加载局域网证书，成员设备信任该证书。HTTP 保留为受控开发模式，不把明文传输与数据库加密混为一谈。
- HTTPS 会话 Cookie 使用 Secure、HttpOnly、SameSite；修改请求校验同源/CSRF，WebSocket 握手也检查会话与 Origin，不把会话令牌放进 URL。
- 公共 WebSocket 事件按团队订阅；成员被移除、账号停用或会话撤销后及时取消对应订阅。私人流只向本人的已授权连接发送。
- 重连先按游标补取持久事件；成员在线状态是短期连接状态，不作为工作进展的证据。实时流事件携带游标，客户端去重并补齐缺口。
- 数据库存放在 `.local/web/team.db`，主密钥独立存放；真实密码、密钥与备份不提交到仓库。
- 用 SQLite 备份机制生成一致快照，单独备份主密钥并验证恢复。WAL 模式下不把单独复制正在写入的 db 文件当作完整备份。
- 关闭部署电脑或服务后，队友暂时无法访问；首版不承诺离线协作与高可用。

## 8. 与现有代码衔接

- 根目录 `server.mjs` 和 `public/` 是单人网页原型，使用全局用户、全局状态和全局模型配置；需要逐步替换为真实身份与分团队请求。
- `experiments/dsh-team/` 中的决定版本、指定确认人、幂等发布等规则可作为参考；其中“每套 dsh 绑定一个成员”的认证方式不直接移植。
- 旧任务卡片、模拟成员和任务完成率不能自动作为新产品需求；浏览器多人基础流程从真实账号与空团队开始。
- 新建 `backend/` 放置 TypeScript 服务、路由、数据库和测试；网页通过明确版本的 API 衔接。
- 开发期给新服务使用独立端口与 `.local/web/` 数据目录。原 `.local/project.json`、旧 AI 配置和 dsh 试用资料保留，不自动导入模拟身份或共享 Key。
- M1 验收后再切换默认启动入口，README 明确新旧原型的运行方式。
