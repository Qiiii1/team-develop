# 核心协作版 · 0.2.0

更新：2026-11-02。运行方式保持本机部署、局域网 HTTPS，每位成员使用自己的 DeepSeek 配置。GitHub Pages 继续作为静态预览，未启用公网转发。

开发交接：完整请求／响应见 [API 接口文档](API.md)，启动、认证和代理配置见[前端联调指南](前端联调.md)。

## 如何使用

登录并进入团队后，有四个入口：「公共讨论」「个人 AI 工作区」「共享成果」「背景与决定」。原有的成员、邀请与权限管理折叠在页面下方的「成员与邀请」。系统管理后台仍为 `/admin`。

1. 在「我的 AI 配置」保存自己的模型名称和 API Key。保存操作只存储配置；只有实际发送个人问题或公共 @AI 消息时才调用模型。
2. 在「个人 AI 工作区」命名并新建对话。新对话带入当时的团队资料包，个人消息只允许本人读取。团队管理员和系统管理员也没有读取他人私聊的接口。
3. 在「公共讨论」直接和队友交流。普通消息不会触发模型，明确提及 `@AI` 才会请求公共 AI；调用使用发出这条消息的成员自己的 Key。公共 AI 的回答对全队可见。
4. 选择消息下方的「作为分享草稿」，编辑标题、摘要与来源链接，先「预览发布」，再「确认发布」。也可手动填写成果。只发布预览中的文字和来源，不会公开整段个人对话。
5. 在「背景与决定」提出草案，并选择指定确认人。确认人可以是任何可用团队成员，不要求具有管理员身份。只有确认人点击「确认生效」，草案才进入生效的团队资料；也可以退回草案。
6. 对已有背景或决定点击「提出修订」。历史版本保留；若已有其他修订先行生效，旧草案不能覆盖新版本，需要重新基于当前生效版本提出修订。

个人消息与团队消息输入框支持 Ctrl / ⌘ + Enter 发送；普通 Enter 换行。公共消息和当前个人对话每 4 秒同步一次；标签页隐藏时暂停同步，返回后继续。分享和版本列表可点击「刷新协作」更新。

## 资料版本与复核

「资料包版本」和「某项决定的版本」分别记录。每次确认背景／决定或发布成果，会产生新的团队资料包。

- 个人对话固定使用创建时的资料包。团队资料更新后显示提醒，可以查看新资料与来源，再由本人选择「采用当前资料」。历史消息保留生成时的资料版本。
- 从旧消息分享或提出草案时，服务端按来源消息确定实际依据，不能通过前端提交其他版本伪造来源。旧资料需要填写复核说明后才可提交；记录继续保留原依据版本。
- 发给模型的资料包包括最近 20 项已生效资料与 20 项成员分享，每项正文截取前 1600 字，并标记是否截取。公共 AI 只接收公共讨论与团队资料，不接收个人私聊。
- 普通讨论、AI 回答、待确认草案和已生效决定分别处理。模型没有直接发布成果、修改资料或替成员确认的工具。

版本历史、资料包和已发布成果保存在本机数据库中。模型上下文窗口使用最近 20 条消息，文本有长度预算；完整聊天记录仍保存，消息列表每页 100 条，可继续查看更早消息。个人对话、成果和资料列表首版最多返回最近 100 项；单项版本列表首先显示最近 30 版并始终包含当前生效版，也可分页查看更早版本。

## 模型调用与失败

模型请求由本机后端发送到固定的 `https://api.deepseek.com/chat/completions`，使用本人已保存的 Key。请求包含对应对话和所用团队资料；公共调用不夹带私人消息。后端不抓取来源链接内容，不向模型提供成员密钥或网站登录令牌。

采用非流式回答，等待期间显示处理状态；60 秒未完成会结束请求。每位成员同时最多发起一个模型请求。模型提供方收到请求后，即使网络中断，也可能已产生用量；本系统不会自动重试或自动重新计费。

消息发送使用 `requestId` 去重：同一请求重放会返回原记录及状态，不再次调用模型。失败记录保留，可编辑后重新发送新请求。服务重启会把未完成调用标为失败，不会自动恢复调用。模型错误响应和任意异常详情不会原样写入公开记录。

已完成 DeepSeek 请求契约的模拟测试，未在开发测试中使用实际 Key 产生付费调用。有效性、实际延迟与额度以成员实际提问的结果为准。[DeepSeek 官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)

## 前端 API 对接

接口前缀为 `/api/v1/teams/:teamId`，均要求登录、当前团队成员资格及未停用的团队。写入接口沿用现有 JSON、同源／CSRF 或明确允许的跨域 Bearer 会话检查。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /context?version=N` | 获取当前或历史团队资料包；不传 version 获取当前版本 |
| `GET /threads`、`POST /threads` | 列出本人对话、新建个人对话（title） |
| `GET /threads/:threadId?before=seq` | 本人对话、使用的资料包、最近或更早消息 |
| `PUT /threads/:threadId/context` | 明确切换对话资料（version、expectedVersion） |
| `POST /threads/:threadId/messages` | 私人 AI 提问（content、requestId） |
| `GET /discussion?before=seq` | 公共消息与最新资料包版本 |
| `POST /discussion` | 公共讨论，检测显式 @AI 后调用模型（content、requestId） |
| `GET /shares`、`POST /shares` | 查看成果、本人确认发布文字成果 |
| `GET /knowledge`、`POST /knowledge` | 查看背景与决定版本、提出新草案或修订 |
| `GET /knowledge/:documentId/versions?before=N` | 分页查看更早的资料版本 |
| `POST /knowledge/:versionId/resolve` | 指定确认人处理草案（action 为 confirm 或 reject） |

`requestId` 使用 UUID，同一发送或发布操作重试时保留；修改内容后应生成新编号。消息结果返回 `prompt`、`answer` 和 `latestContextVersion`。`prompt.aiStatus` 为 pending、complete 或 failed；失败时查看 `aiError`，不会伪造模型回答。

分享请求包括 `requestId`、`title`、`content`，可选 `sourceUrl`、`sourceMessageId`、`basisVersion`、`reviewNote`。来源消息必须是可访问的公共消息或本人的个人消息。

草案请求还需 `kind`（background／decision）、`confirmerId`、`baseVersion`。新资料的 baseVersion 为 0；修订还需 documentId，并使用该资料当前生效版本作为 baseVersion。

文本上限：标题 100 字符，消息／成果／草案正文 6000 字符，来源链接与复核说明 2000 字符。输入字段采用白名单，不接受前端自报的作者、权限或会话归属。

同源网页直接请求相对 API 地址。独立前端设置公开配置中的 apiBaseUrl，并由后端明确允许前端 Origin；继续使用现有跨域会话适配。当前 Pages 预览禁止业务请求，不代表已经接通本机服务。

## 升级与验证

新增迁移 `0002_core_collaboration.sql`，增加协作资料包、个人对话、消息、调用记录、分享、资料与版本表；不删除或重建原账号、团队、Key、会话和管理记录。协作表采用自定义 SQL 迁移，通过同一 SQLite 连接执行参数化查询；其他表继续使用 Drizzle。

正式升级前，使用 SQLite backup 接口为现有数据库创建一致备份，并单独保存加密主密钥。执行 `npm start` 会编译代码并应用尚未执行的迁移。

