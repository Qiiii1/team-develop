# 局域网 HTTPS 配置

以下使用 `192.168.1.100` 作为示例局域网 IP，请替换为部署电脑的实际地址。队友通过 HTTPS 访问，部署电脑也可使用 **https://localhost:4185**。

## 配置内容

1. 查找部署电脑的局域网 IPv4 地址，示例为 `192.168.1.100`。
2. 执行 `npm run setup:lan -- 192.168.1.100`，通过本机 OpenSSL 创建项目专用 CA 与服务证书。
3. 服务证书的 SAN 包含 `192.168.1.100`、`127.0.0.1` 和 `localhost`，有效期一年，以生成证书的实际到期日为准。
4. 将下面配置保存到未纳入版本控制的 `.env.web.local`，停止旧 HTTP 进程并用 `npm start` 启动。

```dotenv
HARNESS_WEB_HOST=0.0.0.0
HARNESS_WEB_PORT=4185
HARNESS_WEB_DATA_DIR=.local/web
HARNESS_TLS_CERT=.local/web/tls/cert.pem
HARNESS_TLS_KEY=.local/web/tls/key.pem
```

`0.0.0.0` 是服务监听配置，成员使用实际的 `192.168.1.100` 地址。脚本不会配置路由器公网转发或外网隧道。

重新配置 HTTPS 时，账号、团队与管理员权限继续使用原数据库。HTTPS 模式下新登录的会话 Cookie 带 Secure 标志。

## 发给队友

- `artifacts/Team-Develop-LAN-CA.crt`：可单独分享的公开 CA 证书。

成员设备首次需要导入并信任此 CA，随后访问 HTTPS 地址、注册账号、使用邀请码加入。项目没有替任何设备修改系统信任设置。使用者必须确认公开证书来自部署者；不要将 `.local/web/tls/ca-key.pem`、`key.pem`、数据库或模型加密主密钥发给队友。

## 重启与地址变化

日常重新启动：

```sh
npm start
```

如果电脑内网 IP 变化，先停止服务，再重新签发覆盖新地址的服务证书：

```sh
npm run setup:lan -- 新的内网IP
npm start
```

脚本复用原 CA，重新生成服务证书、更新本机配置，并输出新链接。成员已信任的 CA 可继续使用。重新签发后应将新地址告知成员；公开 CA 文件仍保持相同。

建议在路由器上为部署电脑固定 DHCP 地址。电脑或服务停止后链接暂时不可用。本次没有设置开机自动启动。

## 验证建议与边界

- 确认服务监听局域网接口的 4185 端口。
- 使用公开 CA 作为信任根访问 HTTPS `/health`，应返回 `{"ok":true}`；不要关闭证书校验。
- 验证局域网页面正常返回、未登录的后台接口返回 401。
- 从另一台真实设备验证网络互访和证书信任。无法访问时，检查 Wi-Fi 设备隔离和电脑防火墙。
- 数据库、数据库备份、主密钥、证书私钥和环境配置不进入 Git。恢复模型配置需要数据库及匹配的加密主密钥，应使用独立、安全的渠道备份。

首次配置脚本依赖 Node.js 与 OpenSSL，后端运行依赖与之前一致；没有安装系统级证书工具或更改全局 TLS 设置。
