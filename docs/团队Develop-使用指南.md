# 团队 Develop · 安装与使用指南

插件版本：**0.0.3** · 文档更新：**2026-10-17**

适用于 macOS 上的 **DeepSeek Harness 0.2.0-rc.2**。本次已验证隔离配置中的安装、卸载、空白初始化和本机共享流程；尚未在朋友的实体电脑上验证。公网连接此前因下载隧道工具超时，尚未实测通过。请先按下面步骤启动共享服务、确认自己能够创建团队，再邀请朋友。

## 先下载哪一个

| 文件 | 给谁 | 用途 |
| --- | --- | --- |
| `Team-Harness-Trial-0.0.3.zip` | 你自己 | 总试用包，包含本指南、下面两份安装包和校验值 |
| `Team-Harness-Host-0.0.3.zip` | 团队发起人 | 安装插件，以及在自己的电脑上启动共享服务 |
| `Team-Harness-Friends-0.0.3.zip` | 发给朋友 | 安装插件，通过邀请信息加入同一团队 |

如果下载的是总试用包，请先完整解压，再分别解压 Host 或 Friends 安装包。发起人只安装 Host 包一次；其中已经包含朋友使用的插件安装程序。

本方案由发起人的电脑保存团队共享数据，通过临时 HTTPS 地址供大家连接。暂时不需要购买服务器、配置域名或另外安装 Node.js。个人对话、AI 模型和本地工作文件仍由各自的 dsh 管理。首次启动共享服务需要联网下载 cloudflared，或者使用已安装的 cloudflared。

## 开始前准备

你和朋友都需要：

1. 安装官方 DeepSeek Harness，将应用放在 `/Applications` 中，并至少打开一次，完成首次初始化。官方入口：[DeepSeek Harness](https://deepseek.com/harness)；项目说明：[官方仓库](https://github.com/deepseek-ai/deepseek-harness)。
2. 使用本插件验证过的 dsh **0.2.0-rc.2**。其他版本尚未验证；如果安装器报告版本不兼容，保留报错信息，先处理版本适配。
3. 如果要使用 AI，先在各自 dsh 中完成模型配置；本插件沿用该配置。手动写进展不要求配置模型。

发起人还需要：试用期间保持电脑开机、联网且不休眠，保留启动服务的终端窗口。

## 一、发起人：安装、创建团队、邀请朋友

### 第 1 步：安装插件

1. 完整解压 `Team-Harness-Host-0.0.3.zip`。
2. 双击文件夹内的 **`Install.command`**。
3. 等终端显示“安装完成”。
4. 完全退出 dsh（`Command + Q`），再重新打开。
5. 在侧栏点击 **团队情况**。首次安装应显示“创建项目 / 加入项目”的空白入口。

如果双击脚本未执行：打开“终端”，输入 `zsh `（末尾有一个空格），将 `Install.command` 拖入终端，再按回车。其他 `.command` 文件也可按同样方式运行。

### 第 2 步：先启动共享服务

1. 双击同一文件夹内的 **`Start-Shared-Team.command`**。
2. 首次启动会下载官方 cloudflared 并检查 SHA-256；后续优先使用本机缓存或已安装的工具。
3. 等待终端显示 **团队服务地址** 和 **创建口令**。地址格式类似 `https://某个临时名称.trycloudflare.com`，请使用终端本次实际显示的地址。
4. 保持这个终端窗口运行。

出现地址只代表启动器取得了临时入口；下一步成功创建项目，才说明插件能够连接到共享服务。如果终端持续报错，先处理连接问题。

### 第 3 步：创建异地团队

1. 在 dsh 的 **团队情况** 中选择 **创建项目**。
2. 填写姓名、角色、项目名称和可选的项目目标。
3. 展开 **连接共享服务**。
4. 将终端显示的地址填入 **团队服务地址**，将口令填入 **创建口令**。
5. 点击 **创建团队项目**。
6. 确认看到自己的成员工位，且没有连接错误提示。新团队没有预置进展、任务或决定。

**创建异地团队时要填写共享服务地址。** 留空会创建仅本机试用的空间。目前每套 dsh 配置只关联一个团队，已经关联后不能直接切换到另一团队。

### 第 4 步：邀请朋友

1. 点击团队页面右上角的 **邀请成员**。
2. 点击 **复制邀请信息**。完整内容以 `th1.` 开头，其中已经包含服务地址。
3. 将下面两项一起发给朋友：
   - `Team-Harness-Friends-0.0.3.zip`。
   - 刚刚复制的完整邀请信息。
4. 创建口令由你保留，朋友加入时不需要填写。

可直接复制给朋友的说明：

> 先安装并打开一次 DeepSeek Harness 0.2.0-rc.2。解压我发的 Friends 包，运行 Install.command，完全退出并重新打开 dsh。进入“团队情况 → 加入项目”，填姓名、角色，粘贴我另外发给你的完整邀请信息。我会在试用期间保持共享服务在线。

## 二、朋友：安装并加入

1. 完整解压发起人提供的 `Team-Harness-Friends-0.0.3.zip`。
2. 双击 **`Install.command`**，等终端显示“安装完成”。
3. 完全退出并重新打开 dsh。
4. 点击 **团队情况 → 加入项目**。
5. 填写姓名、角色，粘贴发起人提供的**完整邀请信息**，不要只复制其中一段。
6. 点击 **加入团队项目**。
7. 确认项目名称正确，能看到自己和发起人的成员工位。

朋友不需要运行 `Start-Shared-Team.command`。完整邀请信息已经包含地址，通常无需展开“连接共享服务”另外填写。

## 三、先用两个人验证一次

建议先用手动进展验证同步，随后再试 AI：

1. 朋友打开 **我的进展 → 手动写进展**。
2. 在“本次进展”中写一小段试用文字。
3. 点击 **预览发布**，核对团队可见内容，再点击 **确认发布**。
4. 发起人打开 **团队总览**，确认能看到这条记录。正常连接时页面约每 1.8 秒刷新一次。
5. 发起人也发布一条进展，朋友确认能够看到。

两边都能看到对方记录后，再邀请更多成员。这些试用文字会成为实际共享记录，请使用可以向队友展示的内容。

## 四、日常使用

### 个人对话与 AI 草稿

在自己的 dsh 工作区中继续对话。希望分享本轮工作时，可以对 AI 说：

> 把这轮工作整理成团队进展草稿。

然后打开 **团队情况 → 我的进展**，找到草稿，修改内容，再通过 **预览发布 → 确认发布** 分享。仅保存草稿不会同步给队友。

如果 AI 没有成功调用草稿工具，可以先手动写进展。插件不会自动上传完整个人对话、本地文件或模型密钥。你确认发布的文字和链接会成为队友及其 AI 可读取的团队资料。

### 查看团队

打开 **团队总览**，点击成员工位，查看对方已经分享的进展、下一步和需要的帮助。当前没有任务状态、进度百分比、自动派活或预置任务。

### 记录关键决定

1. 打开 **关键决策 → 记录决定**。
2. 填写内容、依据和可选来源，指定由谁确认。
3. 提交后，由指定成员点击 **确认生效**。
4. 后续变化通过 **提出新版本** 留下历史；确认前，原来的生效版本继续适用。

如果进展引用的决定有了新的生效版本，页面会提示复核；根据新决定修改草稿后再发布。

## 五、停止、重启与临时地址变化

### 停止

在发起人的服务终端按 **Control + C**。停止后大家暂时无法同步；已经保存的团队记录仍在发起人的电脑上。朋友退出自己的 dsh 不会关闭发起人的共享服务。

### 再次开始

1. 发起人重新运行 **`Start-Shared-Team.command`**，保留原来的 dsh 和共享数据目录。
2. 读取本次显示的 HTTPS 地址；每次重新建立临时隧道，地址会变化。
3. 发起人及已经加入的朋友分别打开 **团队情况 → 连接设置**。
4. 填写新地址，点击 **验证并更新**。验证成功后保留原团队和成员身份，无需重新加入。
5. 发起人更新连接后，为尚未加入的新朋友重新复制邀请信息；旧邀请包含旧地址。

原服务离线时，“连接设置”仍可用于更新地址。如果新地址的服务没有加载原团队数据，更新会失败；此时先确认发起人使用的是原共享数据目录。

## 六、常见情况

| 情况 | 处理方式 |
| --- | --- |
| 提示先安装 dsh | 将官方应用放到 `/Applications/DeepSeek Harness.app`，打开一次完成初始化，再安装插件 |
| 安装后没有“团队情况” | 确认安装终端没有报错，然后完全退出 dsh 再打开；其他 dsh 版本需要另行适配 |
| 安装器提示版本不兼容 | 当前包验证版本为 0.2.0-rc.2；保留完整报错，不跳过兼容性检查 |
| cloudflared 下载超时或校验失败 | 换可访问官方下载的网络后重试；已经安装 Homebrew 的发起人也可运行 `brew install cloudflared`，再启动服务。未安装 Homebrew 时不需要为了朋友端额外安装它 |
| 一直显示“正在建立临时 HTTPS 连接…”或终端报连接失败 | 检查发起人的网络，停止启动器后重试；取得地址后还需要成功创建团队来验证连通性 |
| 加入失败或没有同步 | 确认发起人服务仍在运行、电脑没有休眠；完整复制邀请信息；若服务重启过，更新临时地址 |
| 提示“创建口令不正确” | 核对服务地址和创建口令是否来自同一个正在运行的启动器；朋友应选择“加入项目” |
| 提示“当前实例已经关联团队” | 当前版本每套 dsh 配置只关联一个团队；“连接设置”只更新同一团队的地址，不能切换团队。保留数据，先处理团队迁移 |
| 提示“共享服务已在运行” | 使用已打开的服务窗口中的地址；需要重启时先在原窗口按 Control + C |
| AI 没有生成草稿 | 先确认 dsh 的个人对话可正常使用模型；插件安装后重新打开 dsh 对话，再试一次，也可手动写进展 |
| 卸载后再安装仍看到原身份 | 卸载会保留本机身份和私人草稿；重新安装不会自动清空数据 |

## 七、保存与备份

默认位置如下；自定义 `DSH_HOME` 或 `TEAM_DATA_DIRECTORY` 时位置会不同：

| 内容 | 默认位置 | 说明 |
| --- | --- | --- |
| 发起人的共享团队数据 | `~/.dsh/team-harness-shared/team.json` | 成员、共享进展、关键决定及版本 |
| 发起人的创建口令和连接信息 | `~/.dsh/team-harness-shared/create-key`、`access.json` | 只由发起人保存 |
| 每个人自己的身份与私人草稿 | `~/.dsh/profiles/desktop/team-collaboration/` | 留在各自电脑，加入后的身份用于后续连接 |

需要备份时，先停止共享服务、退出 dsh，再复制相应目录到自己的备份位置。保留成员身份文件和共享数据，才能在重启后继续使用原团队。发给朋友的是安装 ZIP 和邀请信息，不要打包这些数据目录。

## 八、卸载

双击安装包里的 **`Uninstall.command`**，完成后重新打开 dsh。卸载移除插件，保留本机身份、私人草稿和发起人的共享数据。发起人还需在服务终端按 **Control + C** 停止共享服务。

## 当前边界

最多 10 位成员，每套 dsh 配置关联一个团队。当前没有账号找回、成员移除、邀请撤销或多团队切换；公网连接和朋友实体电脑安装尚未验证完成。正式长期使用前还需要进一步完善。

临时连接由 [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) 提供，无需域名或 Cloudflare 账号，适合短期试用；停止进程后地址失效，没有在线保证。
