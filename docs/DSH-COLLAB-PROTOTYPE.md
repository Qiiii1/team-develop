# 团队协作原型 · 2026-10-16

本文记录 0.0.2 的实现和测试。后续 0.0.3 已去掉任务状态、成果阶段与统计卡片，并增加可分发安装包，当前使用方式见 [插件试用说明](DSH-PLUGIN-TRIAL.md)。

在之前已跑通的 dsh 插件上实现三个可操作页面，没有增加预置任务。保留早期验证记录，新增的记录来自本次人工操作测试。

## 团队总览

成员以简化几何工位展示。点击成员，查看负责事项、进展、下一步、阻塞、成果阶段和等待对象。顶部汇总需要协调的人数、待确认决定、依据更新后需要复核的当前进展。

“等待与协作”直接呈现成员之间的等待关系。成果阶段由成员手动确认，不表示系统已经核验完成。

## 我的进展

两种入口：

1. 在本页填写本轮工作记录，用真实 DeepSeek 整理为结构化草稿，也可以手动写草稿。
2. 在 dsh 个人对话中，请 AI “把这轮工作整理成团队进展草稿”。插件的 `team_progress_draft` 工具只保存私人草稿，不具备发布能力。

草稿保存在各实例自己的 `private-drafts.json`。本人可以修改事项、完成内容、下一步、阻塞、等待对象、成果链接和关联决策。点击“预览发布”，检查团队可见内容，再点击“确认发布”。共享服务不接收原始工作记录或完整个人会话。

AI 整理会将所填工作记录、已共享成员和已确认决定发送到本机已配置的 DeepSeek。Key 不返回页面，不写进生成的插件配置。官方 DeepSeek 配置也通过子进程内存供隔离 dsh 对话使用；未配置时仍可手动写进展。

## 关键决策

创建决定时记录内容、依据、可选来源链接和指定确认人。提案在确认前不会替代原来的生效版本；只有指定确认人可以确认最新提案。每次变更新增版本，保留原文、依据、提出人、确认人和时间。

进展可以关联某个已确认的决策版本。新版本生效后，依据旧版本推进的当前进展会显示“依据待复核”。未复核的旧草稿不能直接发布；本人可明确采用最新版本，再发布新的进展。

## 启动与试用

从仓库根目录运行：

```sh
node experiments/dsh-team/start-preview.mjs
```

- 客户端 A：http://127.0.0.1:4181/
- 客户端 B：http://127.0.0.1:4182/
- 两端从原生侧栏“团队情况”进入插件。
- 首次访问需要 dsh 的本地令牌，初始化链接在 `.local/dsh-validation/demo/access-links.json`，仅供本机使用。
- 继续复用桌面版自带的 dsh 0.2.0-rc.2 运行时，独立 home，不修改用户日常使用的 Desktop profile。

建议体验：在 B 的“我的进展”打开待确认草稿，修改后预览；在 A 的“关键决策”查看登录方式的两个版本；在团队总览点击 B，查看等待关系和依据待复核提醒。

## 已完成的验证

- 五项服务测试通过：旧功能回归、并发持久化、草稿隔离与发布、决策权限及版本影响、响应丢失后的幂等重试、AI 输出验证。
- 浏览器实际操作：A 提交并确认 v1；B 用真实 DeepSeek 生成草稿；A 的私人草稿列表仍为空；B 人工发布后 A 看到进展和等待关系；A 确认 v2 后 B 出现待复核提醒。
- 真实 dsh Agent 调用了 `team_state` 和 `team_progress_draft`，创建私人草稿；验证前后团队共享记录数量保持不变。
- 重新启动预览后，成员身份、共享记录、决策历史和私人草稿保留。

```sh
node --test experiments/dsh-team/test/service.test.mjs
node experiments/dsh-team/verify-real-ai.mjs --draft
```

第二条命令会消耗少量已有 DeepSeek 额度并创建一份私人测试草稿。

## 原型边界

当前仍为同一台机器上两个隔离实例的演示，没有云端部署、正式账号、跨机器连接、官方桌面插件安装包或多团队切换。等待关系和工作依据由成员确认；没有自动推断整个项目的依赖图，也不会自动改任务或替人确认决定。
