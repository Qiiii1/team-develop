# 2026-10-14 · dsh 插件验证结果

结论：以 dsh 插件承载真人团队协作的最小流程可行。已经跑通真实插件加载、原生侧栏与主面板扩展、两个隔离客户端共享记录，以及真实 DeepSeek 的团队信息工具调用。

## 证据

| 检查 | 结果 |
| --- | --- |
| 安装环境 | DeepSeek Harness 0.2.0-rc.2，桌面携带运行时，构建 5e9e301 |
| 插件加载 | `index.mjs` 通过 Cordis patch 加载；`client.js` 经 dsh 模块加载器挂载 |
| 界面入口 | 侧栏新增「团队情况」，通过 `sidebar.panellist` 和 `main` Slot 扩展 |
| 成员隔离 | 两个独立 `DSH_HOME`、个人会话存储与不同成员令牌 |
| 共享过程 | A 创建团队，B 通过邀请码加入；进展、阻塞和结论双向同步 |
| AI 过程 | 官方 dsh headless Agent → 真实 DeepSeek → `team_state` → 共享服务 → AI 总结 |
| 个人内容边界 | 仅发布表单允许字段共享；AI 验证只准读取 `team_state`，私人文件哨兵未进入结果 |
| 数据可靠性 | 并发 8 条结论无丢失，服务重启后身份和共享记录保留 |

真实 AI 输出正确识别：成员 A 已确认需求范围，成员 B 已接入团队页但尚未验证跨机器连接；关键结论是首版手动发布进展、个人完整对话不共享。输出同时说明成员上报不等于完成证据。

## 下一步范围

优先验证官方 Desktop profile 的插件安装与卸载，以及两台实际电脑连接同一远程服务。正式账号、邀请有效期、角色权限、云端凭证、按工作区绑定团队和版本兼容策略属于产品化工作。

本次只验证了本机双实例。没有修改 dsh 核心、用户现有 dsh 配置、原型的个人项目或已有聊天，也没有部署云服务或发布插件。
